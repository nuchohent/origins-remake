### Морф: адаптация камеры под моба (12:48) — ВАЖНО
- **Камера (eye-point) подстраивается под голову моба**, хитбокс не трогается (пользователь выбрал: «опустить камеру, хитбокс не трогать»).
- Реализация — **первый миксин в Looks** (раньше их не было): `dev/originsx/looks/mixin/CameraMixin` + конфиг `originsx_looks.mixins.json` (пакет `dev.originsx.looks.mixin`, client: `CameraMixin`).
- **ВАЖНО (13:17, корневая причина — миксин не срабатывал)**: NeoForge НЕ авто-находит `.mixins.json` из jar-ресурсов — конфиг надо **явно объявить** в `neoforge.mods.toml` блоком `[[mixins]] config = "originsx_looks.mixins.json"` (как это делает OriginsX в своём mods.toml, стр. 42-43). Без этого конфиг в jar НЕ подхватывается, и миксин молча не применяется (игра грузится, но камеры не касается, лог `[Looks] camera eye -> mob` НЕ появляется).
- **ВАЖНО (13:40, вторая причина — крэш)**: после объявления конфиг стал применяться, но `@Redirect` κрэшил игру: `InvalidInjectionException ... unexpected argument type Camera at index 0, expected Entity. Handler signature (Camera, Entity)F Expected (Entity)F`. Правило mixin: обработчик `@Redirect` НЕ получает `this` миксин-класса (Camera), а только **receiver + аргументы** перехватываемого вызова. Так как цель — `entity.getEyeHeight()`, сигнатура обработчика — `private float looks$redirectMobEyeHeight(Entity entity)`, без `Camera`. Исправлено, пересобрано, задеплоено 13:40.
- **ВАЖНО (13:44, первое лицо — камера не адаптировалась)**: в 3-м лице адаптация работает, в 1-м нет. Причина: `EntityForm.update()` выкидывал призрака в 1-м лице (`discardGhost()` при `isFirstPerson()` — чтобы тело моба не блокировало крошечный вид изнутри модели), а `currentEyeHeight()` читал `ghost != null ? ghost.getEyeHeight() : 0f` → в 1-м лице = 0 → гард `mobEye > 0` в миксине срабатывал вхолостую → камера оставалась обычной.
- **ВАЖНО (14:06, докручено — устойчивая адаптация в 1-м лице)**: кэш в поле помогал только если призрак УЖЕ был создан (т.е. игрок сначала побывал в 3-м лице). Если игрок сразу в 1-м лице (старт мира), призрак никогда не создавался → `currentEyeHeight` оставался 0 → всё равно не работало. Теперь в `update()` высота глаз считается **статически из типа сущности** (`type.getDimensions().eyeHeight()`) в ветке 1-го лица, до всякого призрака — камера адаптируется даже без существующего призрака. В 3-м лице по-прежнему точное значение из `ghost.getEyeHeight()`. Пересобрано, задеплоено 14:06. (Диагностический лог `[Looks] camera eye -> mob ...` всё ещё в миксине — убрать после контрольного запуска.)
- Суть: `Camera.tick` (строка 87) делает `eyeHeight = eyeHeight + (entity.getEyeHeight() - eyeHeight)*0.5F` — сглаживание камеры к высоте глаз сущности. Миксин `@Redirect` подменяет этот `Entity.getEyeHeight()` на `EntityForm.currentEyeHeight()` (натуральная высота глаз моба-призрака), когда camera-сущность = локальный игрок в форме. Камера плавно опускается/поднимается к голове моба (верблюд — выше, аксолотль — ниже).
- `EntityForm.currentEyeHeight()` = `ghost.getEyeHeight()` (0 если не в форме). Рейкаст/взаимодействие остаются на уровне глаз игрока (затрагиваем только `Camera`, не `getEyePosition`).

### Морф: прицел под камеру + фикс «скольжения» (14:22) — ВАЖНО
Новые жалобы: (1) при ломании блок ломается ВЫШЕ, чем смотришь; (2) при стоянии игрока «скользит как по льду». Обе — следствие разрыва «камера у головы моба, но глаз/хитбокс игрока обычные». Пользователь выбрал: «прицел туда, куда камера» + «разобраться со скольжением». Решение:
- **Прицел = камера (Look, `EntityAimMixin`)** — новый миксин на `Entity`, `@Redirect` вызова `getEyeHeight()` внутри `Entity.getEyePosition(F)` (это и строит origin луча `pick`/crosshair/блок-таргета). Для превращённого локального игрока возвращает `EntityForm.currentEyeHeight()` (голова моба) вместо нормального глаза → луч стартует от головы моба, и ломаешь ровно то, что видишь. Направление (`getViewVector`) не трогаем. Добавлен в `originsx_looks.mixins.json` (client) + хелпер `EntityForm.formEyeHeightFor(Entity)` (возвращает высоту глаза моба или -1).
- **Фикс «скольжения» (RaceAPI, `RaceManager`)** — тестовая раса `copper.json` имеет `"scale": 0.87`, который применялся сервером (маленький хитбокс → глюк физики «едет как по льду»). Для **морф-расы** (в JSON есть `model_entity`) теперь серверный scale принудительно 1.0 (`isMorphRace`): хитбокс/физис полностью обычного игрока (маленький размер моба — чисто визуально, клиент).

## Ключевые решения/конвенции (не нарушать!)

- Канал (alpha/beta/release) выбирается на CurseForge, в строке версии его НЕТ
- Семвер по правилам из PATCH_LOG: мажор только при ломании совместимости
- Баланс: минус = сильно (бафф), плюс = слабо (дебафф); карта весов —
  POWER_TYPE_WEIGHTS в RaceCreatorPanel, метки характера — через powerWeight()
- Инлайн-силы из JSON имеют авто-id (`<раса>_power_<n>`) — тип брать из класса
- Эффекты рас помечаются тегами `raceapi_eff_*` и не затирают зелья игрока
- Грант-флаги переживают снятие расы (анти-рефарм стартовых предметов)
